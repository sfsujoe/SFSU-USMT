# Native migration engine

The engine is connected to the GUI for controlled validation. Synthetic tests establish orchestration/policy/metadata/collision behavior, with harmless real child processes for cancellation. They do not prove real USMT coverage, EFS decryption, Windows account provisioning, share compatibility or re-imaging readiness.

## Prerequisites and package

Keep the complete App/Scripts set, including Sfsu.Engine.psm1, Sfsu.Engine.Native.cs, Sfsu.Policy.psm1, Sfsu.Migration.Ui.ps1 and Sfsu.Launch.psm1. Separately supply the Microsoft ADK payload in App/User State Migration Tool/amd64 and arm64, including core DLLs, MigApp.xml, MigDocs.xml, MigXML.xsd, DLManifests and ReplacementManifests. Vendor files remain Git-ignored and are never edited. Runtime checks enforce PE architecture, matching executable versions and valid Microsoft signatures. Tool hashes/versions are recorded.

GUI launch requests elevation before AD sign-in. Migration also checks elevation and enables the process's existing backup, restore, security, ownership and debug privileges; missing rights stop the operation. No account rights or saved policies are granted/changed. Capture requires Windows 10 or later, restore Windows 11; Server/x86 are rejected. Native x64/ARM64 tools follow the OS architecture. Restore requires the same executable build as capture. Actual OS/build/architecture transitions and language/application compatibility remain acceptance tests.

## Capture and policy

Select signed-out employee profiles, verify directory identities or confirm manual identity/name, then choose Back up selected profiles. The engine rechecks the exact registered SID/path and unloaded state. Location review lists OneDrive account roots, Windows SyncRootManager registrations, Dropbox info.json, Box Drive CustomBoxLocation, known provider roots/caches, redirected folders and unresolved-provider notes. Existing directory targets are resolved to cover junction locations. Add custom Box Sync/Google Drive mirror or stream roots, relocated caches and unregistered providers manually. A dedicated cloud mount on a separate volume can be excluded; excluding the whole Windows/profile volume or the entire employee profile is refused. Uploads are assumed complete; no sync-status audit/gate exists.

Standard Edge/Chrome/Firefox roots are supplemented by policy UserDataDir values, Firefox profiles.ini and manually supplied browser roots. Custom entries use Edge|C:\Path, Chrome|C:\Path or Firefox|C:\Path. Unknown/unreadable locations require technician review. No browser is killed automatically. Selected employees must be signed out for database/hive consistency.

One unique ID/name/computer/Pacific-timestamp backup folder and store is reserved per profile. Existing backups are never overwritten or merged. Exact SID and SID_Classes includes with /ue:* avoid inferring a Windows login from a university ID/folder and avoid RID-prefix wildcards. Native MigDocs retains useful outside-profile/shared documents on fixed drives; unselected registered employee profiles and the toolkit are excluded. No separate Downloads copy or MigUser/MigDocs combination is used.

The engine copies the supplied MigApp/MigDocs files, generates Config.xml and adds versioned campus XML (2026.11.07.1). Defender/antimalware components are disabled. Required CAPI2 certificates, crypto private keys and DPAPI components are explicitly retained; missing components stop capture. Office defaults remain unchanged except unconditional OST exclusion.

Unconditional User/System rules exclude EXE, MSI, OST, TMP, discovered/reviewed cloud roots/caches, Windows/user temporary directories, Defender files/registry and browser caches. Edge/Chrome include Bookmarks/Bookmarks.bak and History with WAL/SHM companions. Firefox includes places.sqlite, favicons.sqlite and companions, bookmark backups, profiles.ini and installs.ini. Cache, Code Cache, GPUCache, cache2, startupCache, shader and Service Worker cache directories are excluded. Client-version/custom-location fidelity requires real tests.

Native /p estimation is retained in Raw logs. The maximum reported cluster-size store estimate is compared with available destination space plus a 10% working margin. An unrecognized size format is reported as unknown, never invented. ScanState uses default compression, no encryption, /efs:copyraw, /c, /r:2, /w:3 and explicit log/progress/listfiles paths. /o and secret-bearing arguments are never used. Config Policies/ErrorControl makes disk-full errors 112/39 fatal; native nonfatal errors continue under /c and are reported. Process exit 3, error/warning lines and nonfatal progress records produce warnings. Other nonzero exits stop dependent work. There is no retry of a whole partly applied migration.

Every compressed Store/USMT/USMT.MIG is verified with UsmtUtils /verify:all (requires exit zero). Exact rule hashes/copies, source OS/architecture, tool evidence, native return codes and store length are retained. Logs, progress, estimates and file lists remain outside StorePath in root Logs/<run>/Raw. Finalized per-backup log snapshots preserve evidence; root logs remain authoritative if copying fails.

## Restore and local accounts

Every selected manifest, captured policy hash, fixed store path, destination identity and local account is checked before any mutation. Prepared/failed/cancelled records and duplicate target identities/names are refused. One existing target local account or employee profile registration/folder stops the whole batch. Domain account existence in AD is expected; its local profile/folder is the collision. Source-folder and saved SAM/local names plus dotted destination-folder variants are checked conservatively. Existing local accounts are never reused.

Each local account has masked password/confirmation fields, required enabled/disabled selection and an Administrators choice defaulting to No. All choices precede restore. The final summary excludes passwords. Read-only SecureStrings live only for the active request, input fields are cleared and retained secrets are disposed on completion/cancellation. Passwords never enter scripts, metadata, reports or command-line arguments. This does not protect against an administrator/debugger or all endpoint memory copies.

Every source store is freshly verified before provisioning; stores and rule files are held read-only through apply. All-target collision checks repeat immediately before mutation. Windows NetUserAdd creates each local account disabled using its individual password and the destination's account/password policy. A creation error stops the batch. LoadState maps only the original source-computer/local name to the recreated destination-computer/same name; domain restore retains the original SID without cross-account mapping. Native apply uses the captured rules and bounded retries.

After apply, the intended destination SID/profile registration must exist. New local accounts are put in Users, receive the requested direct Administrators membership, have effective local Administrators membership verified, and then receive the chosen enabled state with verification. Unexpected inherited membership fails verification. The app does not change domain memberships. On failure/cancellation, only accounts successfully created by this run are disabled; partial data/accounts remain for inspection. Existing/racing accounts are not disabled. No automatic account/source-store deletion, rollback, merge, suffix workaround or reset of existing passwords occurs. Retrying can therefore stop on the preserved collision and require technician resolution.

## Cancellation and truthful results

Long work runs off the UI thread. Native processes start suspended, enter a Windows job with kill-on-close and then resume. Failed supervision terminates the process before execution. Cancel stops the job and descendants, preserving partial evidence. A hard-killed app closes the job too; unfinished journals/metadata remain incomplete. There is no arbitrary migration timeout. Progress is the current native command's reported percentage; otherwise activity is indeterminate, with no fabricated batch percentage.

Live reporting inspects raw-log metadata without reading log contents or denying the native writer. Progress/diagnostic readers use writer-compatible sharing while retaining no-follow/single-link and ancestor guards. Unsafe/unavailable raw links are omitted with a visible warning. A live progress-read or HTML-refresh exception leaves the native job running, switches status to unavailable observation and retains a bounded warning, retrying warning recording after native exit if needed. Required result/journal failures can still stop subsequent stages after native work ends; they cannot produce an accepted verified result. Cancellation and fatal native exits remain independent stop conditions.

Schema-four backup.json states are Capturing, CaptureFailed, CaptureCancelled, CapturedVerified and CapturedWithWarnings. HasMigrationData becomes true only after successful native capture and store verification. Schema-three PreparedOnly records remain readable and cannot restore. Versions 1/2 and arbitrary legacy stores remain unsupported. Passwords/restore credentials are never persisted.

Automatic evidence covers native results, store integrity and destination profile registration, not exhaustive content comparisons or application acceptance. Intended-user EFS decryption needs that user's context; technician AD credentials cannot substitute. EfsDecryptionVerified remains false and final reports retain acceptance warnings. Completed native operations therefore finish as Completed with warnings even without skipped-file errors. Retain the source until omissions, intended-user access and coverage are accepted.

## Controlled VM acceptance

Use designated synthetic identities/disposable stores. Test Windows 10/11 x64 capture, Windows 11 x64/ARM64 restore and applicable ARM64 capture/build/architecture transitions. Cover same-SID renamed folders, offline/manual domain identity and local accounts with different passwords and all enablement/admin combinations. Compare real source/destination files and browser/Office state, including Downloads and useful outside-profile/shared data. Check custom cloud roots/caches, mounted drives, redirects/junctions, unreadable provider configuration and excluded file types. Confirm the intended restored user can decrypt EFS files using migrated keys; administrator access is not that test.

Also test whole-batch collision refusal, password-policy rejection, dependency/signature/version mismatch, insufficient space, nonfatal omissions, corrupt stores/policy, interrupted native work, descendant cancellation, account-finalization failure, snapshot denial and preserved source/account state. Validate real UAC/share/native-handle/off-domain/removable-drive behavior and keyboard/screen-reader/contrast/200%-text acceptance. Source implementation does not authorize a production migration or share deployment.
