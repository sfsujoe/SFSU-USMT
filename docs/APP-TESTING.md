# Application testing

The GUI now connects native capture and restore. Read the [migration guide](MIGRATION.md) for prerequisites, exact policies and controlled VM acceptance. Earlier discovery/UI field reports and synthetic tests do not establish a successful native migration.

## Technician flow

The launcher checks FullLanguage and the effective execution policy before loading unsigned app scripts, and the entry point repeats the checks before imports. Unsupported application-control/Group Policy conditions get an actionable explanation; no saved policy is changed. RemoteSigned is not blanket-rejected, and normal Windows signature/zone enforcement remains in force.

Keep sfsu-usmt.cmd with the complete App folder and preserve Backups, Logs and App/Settings. Normal double-click startup requests UAC when needed, then one Windows CredUI dialog for both share access and AD. Use the full university UPN and password; the shared identity policy still validates account names and suffixes. Readable existing toolkit access is reused; otherwise the same entered credential establishes deviceless UNC access. It is passed in memory to the existing Kerberos AD verifier. Only verified AD success seeds the UI and skips its later automatic login form. Local/already-elevated startup uses the same credential dialog, skipping UAC and/or SMB as applicable. No drive-letter mapping, existing-connection removal, password persistence, endpoint bootstrap script or saved-policy change is introduced. Initial Explorer authentication used to reach the CMD remains separate. Headless/maintenance/BuildUiOnly retain their caller privileges and existing behavior.

Combined-sign-in acceptance: close the app and update Sfsu.Launch.psm1, Sfsu.Credentials.Native.cs, Start-SfsuUsmt.ps1 and Sfsu.Ui.ps1 together in App/Scripts, then double-click the unchanged CMD normally. Confirm UAC when required, one Windows credential dialog with no Remember/save checkbox, then the main UI with no second AD form after success. Confirm an independent successful DirectoryAuthentication report. Test valid UPNs for numeric/alphabetic/p-prefixed accounts, wrong passwords, disallowed suffix/domain-backslash input, explicit retry/cooldown, existing share sessions and conflict 1219. Existing connections must remain intact. Cancelling the credential prompt, or cancelling retry after AD failure, enters manual mode only if exact toolkit access exists; inaccessible-share cancellation must stop. Test SMB success/AD rejection or unavailability separately: AD must remain unverified, with retry/manual choices and failed report preserved. Check ten-minute expiry, subsequent Directory credentials reconnect, window-close/error cleanup, local and already-elevated startup, offline share, missing files and unavailable Logs. Bootstrap failures retain visible errors without duplicate generic parent dialogs. Right-click elevation of an inaccessible mapped CMD can still fail before toolkit code runs. No migration is needed for these launch tests, and no UAC policy change is required. Earlier manual-startup/native-prompt screenshots do not validate this new combined flow.

The main window remains maximized with the SFSU logo, title and linked Academic Technology attribution. Windows owns the initial credential dialog; the existing AD reconnect dialog remains normal-sized and centered. Explicit Kerberos-only signed/sealed LDAP, generalized numeric/alphabetic/p-prefixed logins, manual identity confirmation, ten-minute inactivity expiry and bounded retry remain. Folder spelling is independent of SID verification. Manual domain identity requires confirmed ID/name; local profiles require a display name. Restricted source metadata access is reported instead of misclassified as a link. System/setup/missing/linked profiles remain excluded. See [identity configuration](IDENTITY.md).

Select signed-out profiles, then choose **Back up selected profiles**. Each profile has a location dialog listing cloud roots/caches, redirected folders and unresolved-provider notes. Add missing cloud/custom browser locations and confirm review before capture. Uploads are assumed complete; this is not a sync-status audit. The engine estimates size, captures one unique compressed unencrypted store per profile, and verifies each store without per-file prompts. No existing backup is overwritten or merged.

The Restore tab shows verified captures alongside PreparedOnly/incomplete folders. Only verified schema-four native captures restore. Choose **Restore selected backups**. Every target is checked before account/data changes; any local account or employee profile/folder collision stops all targets. For each local account, enter/confirm its masked password, explicitly choose enabled/disabled and choose Administrators membership (default No). Cancelling any prompt clears retained secrets and makes no account/data changes. The final summary excludes passwords. Accounts are created disabled, data applied and final settings verified. Failure preserves partial data and disables only accounts created by that run. Domain identity remains the original SID.

A separate maximized monitor opens during capture/restore. Its solid pie shows estimated size-weighted workflow progress, alongside large status/profile text, a separate native current-profile/stage bar and elapsed time. Backup estimates all profiles before the first capture. Unknown sizes are labeled as average/equal-weight fallbacks; missing native percentages remain indeterminate. The last 1% is reserved for finalization. Success is green/check, warnings amber/!, failure a full red circle/X with the actual stopped percentage, and cancellation a gray partial circle, all with text labels. Completion remains visible until dismissed. Optional Always on top is session-only; each monitor's report button retains its own operation's report. Keep the complete App/Scripts set, including Sfsu.Progress.psm1, Sfsu.Progress.Ui.ps1 and Sfsu.Progress.Native.cs, and restart after updates.

During capture/restore, **Cancel task** and closing either window require exact **CANCEL** plus **Stop migration**; dismissing confirmation keeps work running. Confirmed cancellation stops descendants without rollback or deletion. Closing the monitor after confirmation waits for the worker to finish stopping. Local accounts are created just before their own restore; journal details identify created destination SIDs and completed stages. **Open latest report** and **Open Logs folder** expose native evidence. Clean runs finish Completed; actual operational problems or missing required evidence still warn/fail. Store verification is not an exhaustive content comparison or intended-user EFS decryption test. In a controlled VM, validate automatic maximization, both progress indicators through capture/verification/restore/finalization, unequal and unknown profile sizes, missing native progress, every terminal state, report binding, close/Cancel races, multiple monitors, actual DPI/contrast and readability from the intended viewing distance.

## Appearance and accessibility

**Theme & Font** (Alt+T) offers six shared themes and 100/125/150/200% text. Use theme saves only App/Settings/appearance.json; Cancel restores the prior selection. There is no endpoint-local setting or main-screen theme-name label. Windows contrast colors override custom themes without changing preferences. Preserve Settings during updates.

Account/location dialogs use shared fonts, accessible names, masked password fields, keyboard access and measured/scrollable layout. Local-account dropdowns use themed owner drawing with native contrast-mode fallback; multiline location fields scroll. Interactive border dragging defers custom layout while native docking/painting continue. Validate actual keyboard focus, grid selection/sorting, status/error announcements, all contrast themes, real DPI/200%-text, mouse resizing and Narrator/NVDA. Synthetic contrast/render checks are not compliance certification.
