# SFSU User State Migration Tool

Project planning and development for a guided employee backup and restore toolkit using Windows User State Migration Tool (USMT).

The portable application now connects native USMT capture and restore for controlled validation. Domain IDs come from a configured AD attribute through exact-SID lookup, or explicit manual confirmation. IDs, Windows account names, UPNs and profile paths are separate. Local accounts retain their username/SID and require an assigned display name. Synthetic tests do not establish real migration, account provisioning, EFS decryption or platform/share acceptance. Read the [migration guide](docs/MIGRATION.md) before VM testing.

Open `sfsu-usmt.cmd` normally. After UAC when required, one **Windows credential dialog** accepts the university account used for both toolkit-share access and Active Directory. Use the full UPN, such as `your-account@sfsu.edu`; numeric, alphabetic and p-prefixed logins remain supported by the shared identity policy. SMB and explicit Kerberos signed/sealed LDAP are checked separately. Successful AD verification opens the app without a second login form. Cancel can continue without AD only when toolkit access already exists. Credentials expire after ten minutes without directory activity. Every selected profile requires a name. **Back up selected profiles** reviews cloud/custom-browser locations, estimates size, captures each signed-out profile to a compressed unencrypted store with `/efs:copyraw`, and runs native store verification. Useful outside-profile document discovery is retained; cloud/Defender/EXE/MSI/OST/browser caches/Windows temp/TMP are excluded, with Edge/Chrome/Firefox bookmarks/history explicitly included. Cloud uploads are assumed complete.

**Restore selected backups** preflights every target and verifies every source store before account/data changes. Existing target local accounts or employee profile/folder collisions stop the whole batch. Domain identity remains the original SID. Each recreated local account gets its own masked password/confirmation, required enabled-state choice and Administrators choice defaulting to No. Accounts are created disabled immediately before their own restore, with destination SIDs/stages journaled and final choices verified after apply. Passwords are session-only and never enter metadata, reports or process arguments. Failed/cancelled runs preserve partial data and disable only accounts created by that run. Clean runs finish Completed; actual operational problems and missing required evidence still warn/fail. New captures require positive selected-profile file-list evidence separately from store integrity; exhaustive content/application/EFS acceptance remains a development test. Both Cancel and window close during migration require typing **CANCEL** before descendants are terminated, without rollback/deletion. App, Backups and Logs follow the package location; existing backups are preserved.

A normal double-click launch uses an in-memory bootstrap to request UAC before collecting credentials, unless the process already has administrator rights. It uses Windows CredUI, without a save checkbox, and supplies that single session-only credential to any needed deviceless share connection and the existing AD verifier. Readable existing share access is reused. No terminal, manual net use, second automatic credential prompt, drive-letter creation or removal of existing connections is required. Retry is explicit with bounded cooldown; cancellation cannot bypass required toolkit access. The app runs in the same elevated process and takes ownership of the verified credential for normal expiry/disposal; no password is passed through UAC arguments, encoded bootstrap data, files or logs. Initial Explorer/share-mapping authentication used to reach the CMD remains separate. Startup errors show saved details only when Logs is writable. Headless/developer/maintenance actions retain caller privileges and synchronous behavior. The CMD is unchanged and may flash briefly; normal double-click remains the intended share entry point. Close/restart and update Sfsu.Launch.psm1, Sfsu.Credentials.Native.cs, Start-SfsuUsmt.ps1 and Sfsu.Ui.ps1 together. Real Windows credential UI/UAC/share/AD acceptance remains pending.

Account renames and unrelated or suffixed profile-folder names are supported through the matching SID. SID/multiple-match conflicts remain blocked. See [Identity configuration](docs/IDENTITY.md) for the shared attribute/suffix policy, manual identity entry and schema-three metadata. Earlier development metadata versions are intentionally unsupported and remain visible as unrecognized. Exclusion counts explain unsupported/system/setup/missing/linked profiles. Runtime path guards reject filesystem links and protect directories during writes. See [Security and maintenance](docs/SECURITY.md) for permissions, bounded reporting, explicit log-retention commands, acceptance checks, and future engine requirements. User-editable scripts are an accepted risk; the application does not provide a security boundary against an administrator or a compromised endpoint.

The main window starts maximized and is titled **SFSU User State Migration Tool**. Its **By Academic Technology at SF State** attribution links to [Academic Technology](https://at.sfsu.edu/). The existing **Directory credentials** reconnect dialog remains normal-sized and centered, explains that AD resolves SFSU ID to Display Name, and prefixes authentication failures with ⛔. Initial normal startup uses the combined Windows dialog described above. Profile discovery excludes the Windows setup account `defaultuser0` by exact account or profile-folder name, ignoring case; its files and account are not modified.

Capture/restore opens a separate **maximized progress window** with a solid pie for estimated size-weighted overall progress, a separate current-profile/stage bar and large status text. Success fills the pie green, warnings amber and failure red with an X; cancellation remains gray and partial. Outcomes remain visible until dismissed. Native percentages can be unavailable, in which case the current bar is indeterminate. Overall progress includes verification/finalization and is not an ETA. Optional Always on top, elapsed time and the operation's report are available. Closing during migration uses the same typed CANCEL protection. Keep the complete App/Scripts set, including all three Sfsu.Progress files, and restart after updating.

**Theme & Font**, at the bottom right (Alt+T), previews SFSU Classic, Ocean, Forest, Warm, Dark Mode, or Windows system colors and offers 100–200% text sizes. **Use theme** saves the shared preference inside `App/Settings/appearance.json`; all technicians using that toolkit load it on their next launch. No per-computer or per-user preference file is written. Windows high contrast overrides custom colors automatically without changing the saved choice. Cancel/Escape restores the previous appearance. The main screen has no theme-name label. Keyboard access, readable verification text, accessible names/status notifications, wrapping actions, and resizable dialogs support accessibility; full assistive-technology/Windows contrast/DPI acceptance testing remains necessary before claiming compliance.

Printer migration is deferred as a future optional add-on. University printers are assumed to use onsite direct TCP/IP or IPP; personal printers can use uncontrolled installation methods. No dedicated printer inventory, queue recreation or driver deployment is implemented; default USMT components may still attempt their built-in printer handling. The proposed scope and unresolved compatibility/user-context questions are recorded in the runbook.

Successful native migration and store verification now show **Completed** when required application checks also pass. Native diagnostic warnings remain available in the report's WARNING filter as **WARNING (diagnostic)** and in the original Raw files. Native warning exit code 3, recorded ignored errors, unavailable required evidence and failed checks still warn/fail. Past reports are not rewritten. This result-policy change does not repair or add printer migration.

## Local reference archive

Legacy scripts, the UI mock-up and logo, and the supplied USMT toolsets are retained locally in `archive/legacy-and-mockup/`. That folder is ignored by Git and is not included in a clone of this repository. Links into it in the project records require the local reference copies.

The archived scripts operate on employee data and are reference material. They are not the new production toolkit.

The supplied logo under `App/Assets/` is included with the application source. User-supplied ADK files under `App/User State Migration Tool/amd64` and `arm64` are Git-ignored and must be supplied separately with their DLLs, XML and manifests. The GUI/report preview can open without them; migration checks required files, native architecture, matching builds and Microsoft signatures and refuses invalid/missing dependencies. Keep the complete App/Scripts set, including the new engine C# source and policy/UI modules, beside the launcher. Runtime Backups, Logs, App/Settings and tests/.work remain ignored and must be preserved during updates. Developer-only synthetic reports remain available with `sfsu-usmt.cmd -Headless -Scenario Failed`.
